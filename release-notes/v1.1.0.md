修复一类脚本认不出的崩溃，并把"每次都要写一长串路径"这件事解决掉。

## 你会看到什么

- **新增第三类故障：登录态。** 桌面端启动时如果报 `desktop welcome: Web authentication failed`，真凶是应用数据目录里的 `Cookies`，和插件、配置、依赖都无关。新命令 `dsh-rescue reset-cookies` 会把 `Cookies` / `Cookies-journal` 改名成 `.bak-时间戳`（**不删除，可退回**），重启后重新登录即可。
- **诊断现在会把日志里那行错误打出来。** 之前只认三个关键词，遇到新类型既不显示错误、也给不出方向，只能干瞪眼。
- **装一次短命令。** 跑一次 `install`，之后就是 `dsh-rescue diagnose`；不用再记 `pwsh -File "<一长串路径>"`，也不会再遇到 `$r` 没定义、`.\dsh-rescue.ps1` 找不到这类问题。
- **`status` 会顺带报登录态是否健康**（0 字节 / 文件头不对 / 残留非空 journal 三种都能认出来）。

## 行为变化

- 不带参数运行等于 `status`。
- `diagnose` 的"判断"段改成按实际错误分型；认不出来会明确说认不出来，不再套用某一类的修法。

## 验证

- `diagnose` 对三份真实崩溃日志分别判出甲类 / 乙类 / 丙类。
- `reset-cookies` 在假目录上验证：坏 Cookies 被改名、健康 Cookies 不误报、非空 journal 判坏。
- `install` 连跑两次，profile 里仍只有一份标记块。

## 安装

把 `dsh-rescue.ps1` 放到 `C:\Users\<你>\.dsh\rescue\`，然后跑一次：

```powershell
pwsh -NoProfile -File "$env:USERPROFILE\.dsh\rescue\dsh-rescue.ps1" install
```
