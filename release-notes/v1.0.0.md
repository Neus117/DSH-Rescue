首个版本。

DSH 桌面端起不来时，用它把 profile 救回来。**只动配置层，会话、附件、记忆、锚点、凭据一律不碰。**

## 你会得到什么

- **先分清故障类型，再决定怎么修。** 诊断只认两类，因为修法互斥：装载树没起来（`N required plugins did not activate`）走"先退到最小配置再装回去"；宿主启动时读字段失败走"回退依赖树"。用错一条不但无效，还会把插件配置一起丢掉。
- **每一步都能退回去。** `minimal` 和 `restore` 动手前自动存快照，`rollback` 会列出所有快照（时间、原因、依赖数）让你挑，不是只给"上一步"。
- **版本不会被悄悄改掉。** 快照里带 `pnpm-lock.yaml` 时按它冻结安装，避免 `^0.3.8` 这类写法解析出一个没验证过的新版本。
- **应用在跑就不动手。** 检测到进程直接拒绝执行，避免"改到一半应用还在读"。

## 验证

在**复制出来的 profile 副本**上跑完整链路：`minimal` → `restore`（实际装 8 个依赖）→ `rollback`，全部退出码 0；`status`、`diagnose` 在"依赖为空"和"依赖齐备"两种状态下都正常。

## 安装

把 `dsh-rescue.ps1` 放到 `C:\Users\<你>\.dsh\rescue\`，然后：

```powershell
pwsh -File "$env:USERPROFILE\.dsh\rescue\dsh-rescue.ps1" diagnose
```
