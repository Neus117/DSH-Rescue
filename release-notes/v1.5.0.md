新增第五类故障（`.env` 越权），并补上"列快照"命令。

## 这一版是被自己上一版的建议打出来的

我上一版建议"把 `DSH_PET_UNIFIED_MEMORY` 写进 `~/.dsh/.env`，就能正常双击启动"。**这是错的**：宿主对 `.env` 里的键做白名单校验，写进去会直接拒绝启动：

```
DesktopHostFatalError: dsh: .env sets "DSH_PET_UNIFIED_MEMORY", which only the launching
environment may set ...; export it instead of putting it in a .env file
    at readEnvLayer (dsh-app-boot/lib/index.js:4468)
```

## 你会看到什么

- **戊类故障**：`diagnose` 现在认这一类，并且**从日志里把键名抠出来**直接告诉你（`键名：DSH_PET_UNIFIED_MEMORY`）。
- **新命令 `fix-env`**：从 `.env` 删掉那一行，先自动备份；找不到那行会说"可能已被删过"，不会乱改别的键。代理三件套（`HTTP_PROXY` 等）是允许的，不会被碰。
- **新命令 `snapshots`**：列所有快照，带**依赖数**、**是否带 BOM**、**有没有补丁**，并直接标出"空配置 / 带 BOM 别用"。选快照不用再猜名字。
- **`-Snapshot` 的报错不再像"脚本坏了"**：帮助里写清了"必须带名字，先跑 `snapshots`"。

## 验证

- `dsh-rescue snapshots`：12 份快照，正确标出 `deps=0 ← 空配置` 与 `← 带 BOM，别用`
- `dsh-rescue diagnose`：把 00:54 那次崩溃判为戊类并点出键名
- `dsh-rescue fix-env`：键已被删的情况下正确提示"没找到这一行"，不改动其余内容
- 恢复现场后核对：8 个依赖、113 个包、补丁代码在位、`package.json` 无 BOM

## 安装

```powershell
pwsh -NoProfile -File "$env:USERPROFILE\.dsh\rescue\dsh-rescue.ps1" install
```
